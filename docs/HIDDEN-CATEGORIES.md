# Per-device hidden categories

The secure v2 active playlist carries category_settings_version 1, category_provider_generation UUID, opaque category_config_revision hc1_<64 hex>, and hidden_category_ids with exact-string live/vod/series arrays. Movie UI entries map to vod. Leading zeros, media namespaces, device codes, playlist identities and provider generations remain distinct. The live public wrapper was checked read-only before implementation. A revision is not ordered or an authorization token.

Policy is encrypted in the panel provider vault. It is installed synchronously before preparing provider jobs or delivering any cache. A valid changed policy invalidates generation tickets, disconnects current provider connections, purges episode caches and atomically replaces catalogue chunks with the filtered snapshot. A durable policy write precedes catalogue publication; cached() repairs an interrupted rewrite before returning a snapshot. Unknown/empty membership is withheld under a hide policy. A device/playlist/provider epoch change clears the previous scoped catalogue. Existing pairing denial, expiry and 24-hour offline lease remain authoritative.

Missing extension fields mean the documented legacy-empty sentinel. Recognized v1 requires all arrays, bounded exact digit-string IDs and valid generation/revision shapes. Malformed or unknown versions retain only the existing matching device/playlist/provider policy, never implicitly clear hides. With no compatible valid policy, provider content loading waits. An explicit valid empty policy removes prior hides. Network failures do not change it. M3U ignores this Xtream extension and still transfers its bulk playlist; M3U hiding is unsupported.

Each Xtream media fetch reads its categories first, immediately removes hidden IDs and schedules only category_id-scoped item requests. No categories or no visible categories means no item requests. A failed category request never falls back to fullcatalog. A provider ignoring category_id is marked fullcatalog-only per media; only items with matching nonempty membership are accepted, and hidden/missing memberships are discarded before persistence. Shared category_ids are retained and all memberships must be visible. Such providers can still send hidden bytes in the bulk reply, so network savings cannot be promised. No HTTP response bodies or credentials are logged.

Hidden series info and stale playback objects are blocked at repository entry points. Episodes inherit the parent's memberships. In-flight generations are checked before each row/request and before cache commit. Playback rechecks parent visibility on every manifest/segment/key/subtitle request. Main-thread policy delivery stops playback, clears detail/list selections and pending artwork targets, and redraws from filtered data. Posters use no disk or memory cache. Known shared memberships persist as payload-free, explicitly device/playlist/provider-scoped ownership records so a visible-only refresh cannot resurrect an item whose other membership is hidden. Favorites/history/reorder retain opaque IDs at most, not hidden payloads, and display from the visible catalogue only.

A policy-only change requests category metadata, not the newly unhidden items. Opening an explicit category fetches that category lazily. A separate intentional provider refresh still synchronizes currently visible categories. There is no push delivery guarantee; the existing secure config cadence applies server changes after the next successful refresh.

Verification uses Robolectric/fake provider traces, cache and concurrency tests; it does not establish Android TV hardware playback, physical RAM behavior, real provider category compliance or measured speed gains. Source changes are local only.
